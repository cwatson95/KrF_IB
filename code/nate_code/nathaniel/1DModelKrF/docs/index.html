F2-sweep-KrF

A one-dimensional charged-fluid, chemistry, circuit, and electron-energy model for discharge-pumped KrF* at 248 nm and ArF* at 193 nm, coupled to a transverse zero-dimensional optical cavity and production-oriented F2 concentration sweeps.

This page describes the current repository: its data contracts, runtime flow, numerical ownership, public interfaces, outputs, and known limits.

Orientation

The simulated spatial axis is the electrode gap. Charged species and electron energy occupy cell-centred one-dimensional fields; electric fluxes live naturally on faces. The optical gain axis is transverse and is not spatially resolved. Its state is one cavity-averaged photon density. This is therefore a 1D discharge + 0D cavity model, not a multidimensional radiation-hydrodynamics code.

Architecture and runtime flow

  1. Validate specs.
    Grid1D, gas, plasma, preionization, cavity, circuit, coefficient, and numeric settings fail early on invalid ranges.
  2. Build state.
    Create the SI mesh, seed neutral and charged fluids, enforce initial quasi-neutrality, and compile the selected network.
  3. Prepare data.
    Validate reaction-bound cross sections, build or load the coefficient LUT, load ion mobility, and partition chemistry.
  4. Exchange each step.
    Advance the circuit, solve the field, transport charged species and electron energy, and return current/conductance to the driver.
  5. Advance sources.
    Resolve electron sources and energy together; at the fluid cadence advance heavy chemistry and the scalar optical cavity.
  6. Observe and export.
    Record requested diagnostics and progress, flush the final partial cadence, then write HDF5 and declared plots.

The orchestrator owns ordering. Transport does not independently integrate chemistry, chemistry does not own radiative or stimulated rows, and diagnostic collectors do not select figures. These ownership boundaries keep charge, particle, photon, and energy bookkeeping attached to the operation that changes each inventory.

Declarative API

An experiment is configuration plus opt-in observations. The production combination is a mean-energy-keyed two-term table, MPC circuit, source-coupled electron energy, and parallel sweeps when scanning F2.

from Fluid1D import (
    BoltzmannSpec, Cavity, CircuitSpec, DataRef, GasMixture, Grid1D,
    LinePlot, Numerics, OpticalGain, Plasma, Preionization,
    ProgressReport, Simulation,
)

sim = Simulation(
    name="arf_baseline",
    grid=Grid1D(cells=256, length=12e-3, area_m2=90e-4),
    gas=GasMixture(
        {"Ne": 0.9639, "Ar": 0.035, "F2": 0.001, "Xe": 0.0001},
        pressure_atm=3.4,
    ),
    plasma=Plasma(
        density=1e16,
        ion="Ne+",
        electron_mean_energy_ev=2.0,
        secondary_emission_gamma=0.05,
    ),
    preionization=Preionization(
        mode="tanh", amplitude=1e14, floor=1e13, steepness=100.0,
    ),
    cavity=Cavity(wavelength_nm=193.0, r_out=0.08, r_back=0.99),
    boltzmann=BoltzmannSpec(
        backend="two_term",
        key_kind="mean_energy_eV",
        cache_dir="runs/lut_cache",
    ),
    circuit=CircuitSpec(backend="mpc", v0_v=-18e3),
    reactions="data/reactions/arf.toml",
    diagnostics=[OpticalGain()],
    plots=[LinePlot(
        filename="gain_history.png",
        x=DataRef("optical_gain/times_ps", "time (ns)", scale=1e-3),
        y=(DataRef("optical_gain/gain_per_m", "net gain"),),
        ylabel="optical gain (1/m)",
    )],
)

sim.run(
    Numerics(
        steps=4000,
        dt=50e-12,
        fluid_every=20,
        electron_energy_closure="source_coupled",
    ),
    progress=ProgressReport(every=None),
)

Simulation.run builds fresh mutable state, advances exactly the requested number of steps, flushes any chemistry/optics remainder, exports the selected diagnostics, renders the selected plots, and returns output_dir/name.

Species, state, and units

Species is immutable metadata: name, mass, signed integer charge, category, constituents, excitation energy, metastability/relaxation metadata, and an optional photon wavelength. SpeciesRegistry preserves insertion order and supplies category, charged, and excited selections. The full excimer registry contains 45 identities:

  • Electron: e-
  • Ground atoms/buffers: Kr, F, Ne, He, Ar, Xe
  • Atomic excited states: Kr*, Kr**, Ne*, Ne**, He*, Ar*, Ar**, Xe*
  • Charged atoms/lumped ion: Kr+, F-, Ne+, He+, Ar+, Xe+, M+
  • Ground molecular/charged dimers: F2, F2+, Kr2+, Ne2+, Ar2+, ArKr+
  • Excited molecules and excimers: F2*, F2(a3), F2(A1), KrF*, Kr2*, Kr2F*, Ne2*, Ar2*, ArF*, Ar2F*, ArKrF*
  • Photon modes: hv80, hv95, hv147, hv193, hv248, hv415

Neutral and charged fluids store per-cell number-density arrays keyed by the shared registry. Photon modes are registry identities but the lasing mode inventory is the scalar cavity state. Initial electrons are balanced only with a registered positive ion, using n_i = n_e / z_i.

Unit contract

Runtime arrays and coupling constants are SI: metres, square metres, cubic metres, seconds, volts, amperes, joules, pascals, kelvin, m^-3, and m^2. Electron energies and temperatures use eV; reduced field uses townsend. Reaction and cross-section loaders convert tagged source units once at ingestion.

Units(volume="m" | "cm") changes only the user-facing spatial/volumetric convention. Length, area, seed density, gain/absorption inverse length, and diagnostic density labels are converted at the boundary. Electrical, thermal, eV, and E/N values are unchanged.

Pair schema and validation

  • JSON schema cross-section-metadata/1.1 names data_file, data_kind, process_id, reaction text, type/category, projectile, target, threshold, axes, CSV units, source units, conversion provenance, source/database citation, comments, and sample bounds.
  • CSV comments mirror key provenance. Live total tables use energy and cross-section columns; loader-side unit factors convert them to eV and m^2. The provenance-only conversion_from_source field is not applied again.
  • The loader rejects unsupported schemas/units, malformed shapes, and negative or non-finite values. Energies are sorted, duplicate energies are deterministically averaged, interpolation is linear between samples, and values clamp to measured endpoints instead of extrapolating. Threshold behavior remains zero below threshold.
  • Reaction import verifies projectile, target, process kind, and declared stoichiometry. Simulation retains a per-row import report and warns on failures before time integration.
  • The general loader also understands differential tables, and tests exercise that interpolation surface; no differential dataset is part of the live 26-pair production inventory.

Ion mobility and diffusion

ion_mobility.toml stores ten cited or explicitly estimated ion/background pairs as standard reduced mobility K0 in cm^2/(V s), referenced to the Loschmidt density. Loading converts each record to the invariant mu*N = K0*N0.

  • Available mixture pairs combine through Blanc's law. Fractions are renormalized over only the represented background gases.
  • If an ion has records but none match the mixture, the record for its most abundant represented gas is used.
  • If the ion itself has no table entry, charged transport emits a warning and uses the visible generic invariant corresponding to approximately 1 cm^2/(V s) at Loschmidt density.
  • Local mobility is mu = (mu*N)/N_gas; diffusion follows the thermal Einstein relation D = mu*kB*Tgas/e.

Electron transport never comes from this table; it comes from the selected electron coefficient solver.

Chemistry, integration, and electron-energy closure

FluidChemistry assembles the combined neutral and charged mass-action system. For reaction r, its rate of progress and density source are:

R[r] = k[r] * product_s(n[s] ** O[s, r])
dn/dt = nu @ R

The compiler retains padded reactant tables, analytic Jacobian structure, heavy-atom composition, reaction IDs, dynamic-rate masks, charged/electron-changing masks, and one explicit reaction-energy-cost vector. Zero-safe products avoid dividing by initially absent excited species.

Partitions and cadence

  • The electron-source partition includes electron-impact and analytic Te-dependent rows, net-electron-changing rows, and explicitly energy-consuming rows. Its per-cell coefficients are refreshed from live mean energy.
  • The heavy-source partition contains the remaining chemistry and is graded on reactions that change any charged species, not only electrons.
  • The orchestrator tightens chemistry cadence when the fastest fractional progress would exceed its e-fold target. Internal cell substeps are likewise sized by stiffness and available electron energy.
  • FluidIntegrator is the Numba-parallel linearly implicit production path. FluidChemistry.integrate_reference is the single-cell SciPy Radau oracle used for validation.

Production energy identity

Numerics(electron_energy_closure="source_coupled") is the production closure. Transport ledgers field work and elastic exchange; the orchestrator rectifies the unresolved negative sub-Debye sheath contribution and delivers the usable local heating inside the augmented electron-source stage. Reaction extent and its energy debit are accepted from the same implicit trial. Per cell, the stage preserves:

E_final + E_cost - E_bound_adjustment - E_delivered = E_initial

Field work, elastic transfer, accepted cost, delivered source, discarded/undelivered work, coefficient-bound adjustment, residuals, and limiter activity remain separately visible. Positivity reduction scales reaction progress along its stoichiometric direction rather than independently clipping species.

Diagnostic closure: continuous_reconciled applies a provisional continuous inelastic sink in transport and refunds it as an in-stage rate while recording a signed reconciliation. Its archive is marked diagnostic-only and must not be described as a production- conservative result.

Charged transport, field solve, and MPC circuit

The charged model advances continuity with flux Gamma = -D*grad(n) + z*mu*n*E. Interior faces use exponential-fitted Scharfetter-Gummel fluxes, with centered behavior at small Péclet number and stable drift-dominated behavior at large Péclet number. Electrode faces include drift-limited loss and cathode secondary electron emission. The energy flux uses its own mobility and diffusion pair.

  • Poisson: finite-volume, cell-centred potential with Dirichlet electrodes and E native on N+1 faces. Cell E is the adjacent-face average.
  • Semi-implicit conduction: the field solve uses epsilon0 + h*sigma so ohmic current responds to the new field while explicit diffusive current remains on the right-hand side. This removes the explicit dielectric-relaxation limit in the conducting phase.
  • Prescribed drive: a duck-typed at_batch(positions, t) provider is superposed at both cells and faces.
  • MPC: state [V_C0, I_m, V_p, I_s, V_b, I_f, V_Cf] represents the storage capacitor, magnetic switch, peaking capacitor, stray loop, finite gap capacitance, and R-L-C snubber. Frozen linear subflows advance by an augmented matrix exponential.
  • Gap coupling: production uses a first-order Lie split. The MPC network advances with the plasma gap open, transport advances finite-capacitance gap draw, and the resulting node-B voltage is pinned back into the circuit. Booked gap energy is bounded by capacitor stored-energy change.

NumPy and Numba paths

The readable NumPy implementation is the arithmetic reference. The production Numba kernel performs the coupled field/transport substep loop—including coefficient lookup, SG fluxes, wall fluxes, tridiagonal solve, and electron energy—in one compiled call. Kernel changes are required to retain NumPy parity and pass with NUMBA_BOUNDSCHECK=1. Parallel F2 workers set one Numba thread because process-level sweep concurrency is the outer parallel axis.

Scalar cavity, PHOTO feedback, and energetics

PhotonDensity evolves the scalar cavity average as a linear frozen- coefficient equation dn_ph/dt = a*n_ph + b, using an exact exponential update and exact time-integrated photon fluence. GainCavity subcycles when gain, stimulated depletion, spontaneous decay, or photoabsorption hazards become large, re-reading upper-state and absorber densities during the call.

  • Net gain is n_upper*sigma_STE - sum(n_absorber*sigma_abs); round-trip loss includes the output coupler, rear mirror, and configured F2-dependent optical loss.
  • Spontaneous and stimulated hazards share the exact booked upper-state loss, and all declared product multiplicities are applied. last_se_sink_m3 and last_ste_sink_m3 expose the attribution.
  • PHOTO reactions consume the absorber, apply declared products, and remove one cavity photon per physical extent after gain/cavity-volume conversion. Their exponential hazard is driven by the same frozen fluence that attenuates the field.
  • ArF R40/R41 create photoelectrons at fixed row-declared energies 3.76 eV and 3.02 eV. KrF R43/R44 use 3.10 eV and 1.60 eV. The added electron energy is ledgered and the transport-owned electron energy density is resynchronized after optics.
  • Photon inventory occupies the full cavity volume l_c*S. Upper-state inventory occupies the pumped gain volume l_g*S.
  • Output power is the interval average obtained from integrated fluence. Input power is also recorded per interval. LaserEnergetics integrates both as sum(P_average*dt_interval), including first and final partial intervals.

At run end, all selected collectors write one diagnostics.h5. The experiment's LinePlot and HeatmapPlot declarations then select HDF5 datasets through DataRef.

Live reporting, heartbeats, and F2 sweeps

Single-run reporting

Simulation.run(progress=ProgressReport(...)) reports independently of verbose. The final step always emits even when the cadence is uneven. Default fields are system-aware: excimer resolves to the compiled stimulated channel's upper state. Available fields are:

  • total:<species>
  • density:<species>
  • temp:<species> (electron Te; other species report unavailable)
  • excimer
  • photons
  • gain
  • p_in, p_out
  • efficiency

Style is percent or step count. Timing adds wall elapsed/ETA. Terminal output flushes immediately. With heartbeat=True, the reporter atomically replaces progress.json with schema-1 status, step, percentage, simulated time, wall time, timestamp, and formatted fields. Heartbeat write failure warns once and disables that sink without stopping physics.

Parallel sweep contract

sweep_f2_parallel is the production sweep entry point. It accepts either an inclusive start/stop/step range or an explicit unique value sequence in [0, 1], never both. Every point receives a fresh Simulation with the base grid, plasma, preionization, cavity, reaction path, Boltzmann and circuit specs, units, drive, output root, cross-section path, and ion-mobility path preserved. Only the F2 fraction and selected rebalance gas change.

  • diagnostics_factory(f2) and plots_factory(f2) create fresh per-point observations. Parallel factories must be picklable.
  • An injected mutable plasma model or coefficient table is never silently reused. A base simulation containing one requires a corresponding picklable plasma_model_factory(f2) or coeff_table_factory(f2).
  • Workers are pinned to one Numba thread. The parent prints start, completion/failure, periodic running/queued rollup, ETA, and final summary lines when progress is enabled.
  • Worker exceptions become SweepFailure records containing the message, traceback, point directory, and wall time. Other points continue. Abrupt pool death is folded into failure records for all uncollected points.
  • Successful points are sorted by F2 and expose output energy and intrinsic efficiency. Failed points remain separately sorted in SweepResult.failures.

sweep_f2 follows the same configuration/factory contract serially and is the validation path. An explicitly supplied solver overrides the base coefficient backend; it is never substituted implicitly.

# Watch worker heartbeats from another terminal.
python -m Fluid1D.sweep_status runs/krf_f2_sweep --watch 5 --stale 120

The status reader marks old running heartbeats as stalled, shows missing data, and retains failed tracebacks in per-point JSON for post-mortem inspection.

Setup, development, and verification

Python 3.11 or newer is required. Runtime dependencies are NumPy, SciPy, Numba, Matplotlib, and h5py; Linux can use TBB when available. Setup scripts create a virtual environment, install pinned dependencies, and install this repository as an editable package.

./MacOS-setup.sh                 # macOS
./Unix-setup.sh                 # Linux
# .\Windows-setup.ps1          # Windows PowerShell
source .venv/bin/activate

# Complete repository suite
python -m unittest discover -s tests -p "test_*.py"

# Required bounds-checked kernel coverage
NUMBA_BOUNDSCHECK=1 python -m unittest tests.test_transport_kernel

# Fast end-to-end sweep smoke runs
python examples/arf_f2_sweep.py --tiny
python examples/krf_f2_sweep.py --tiny

# Production convergence workflow / restart
python examples/arf_convergence.py --resume

In restricted environments, set writable NUMBA_CACHE_DIR and MPLCONFIGDIR. Numerical changes should add a focused regression. Transport kernel changes require both NumPy parity and bounds checking; chemistry and optics changes should pin conservation against an analytic or reference path.

Verification anchors

  • Coefficient key monotonicity, re-key equivalence, cache identity, measured-table interpolation, Maxwellian moments, and two-term limiting cases.
  • Poisson/Gauss-law behavior, semi-implicit current continuity, circuit stored energy, passive gap collapse, and finite-capacitance energy bounds.
  • Scharfetter-Gummel flux behavior, wall conditions, source-coupled energy identity, positivity, atom/charge conservation, and NumPy/Numba coupled-path parity.
  • Exact photon solutions, high-gain inventory bounds, PHOTO atom/charge/photon/energy feedback, SE/STE attribution, and interval power integration.
  • Final-cadence flushing, units equivalence, diagnostic accessors/archive paths, run-owned plots, live reporting, sweep cloning, failure isolation, and status rendering.

Limits and interpretation

  • Dimensional reduction: discharge dynamics are one-dimensional and optics is a single cavity average. Transverse discharge structure, optical mode shape, and multidimensional propagation are outside the model.
  • Convergence is required: a completed run or passing unit suite is not evidence that a particular mesh, timestep, coefficient grid, chemistry cadence, or network reduction is quantitatively converged.
  • Production choices are explicit: predictive work uses the two-term backend, MPC transport, and source_coupled. Analytic stub/fixed-voltage runs exercise plumbing; continuous_reconciled is diagnostic-only.
  • Electron distribution: the live fluid retains electron mean energy, not a cell-resolved EEDF. The EEDF collector reconstructs one qualitative domain-mean Maxwellian.
  • Ion data coverage: some ion/background combinations use the documented generic reduced-mobility fallback. Quantitative mixture work should add cited swarm data for every populated ion and relevant neutral.
  • Network orphans: the production ArF data retain the literature's Xe+ charge orphan and an Ar2F* state without a declared loss. Their importance is run- and timescale-dependent.
  • PHOTO birth model: current rows inject a fixed mean photoelectron energy derived from photon energy minus binding/detachment energy; they do not sample a sourced kinetic-energy distribution.
  • Coefficient gaps are visible: reaction import failures warn at build. Real coefficient solvers consume the datasets directly and assign zero to a missing electron-impact channel; a warning is therefore a modeling failure to resolve, not an automatic analytic replacement.
  • Gas state: pressure and gas temperature are configured background conditions. Ion diffusion uses that temperature; there is no separate gas thermal or hydrodynamic evolution equation.
  • Data provenance matters: arf.toml is a cited, corrected Chen-derived working network, while arf_chen_2025.toml is explicitly a reproduction overlay. They answer different questions and should not be interchanged.
